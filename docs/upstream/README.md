# Vue Vben Admin 上游同步档案

本目录记录当前项目对 [`vbenjs/vue-vben-admin`](https://github.com/vbenjs/vue-vben-admin) 上游提交的评估、同步和过滤结果。

当前项目只保留 `admin` 与独立维护的 `server`。上游变更不会直接合并，必须按固定基线到目标版本的 first-parent 历史逐项评估。

## 快速入口

| 同步周期 | 上游范围 | 状态 | 提交数 | 档案 |
| --- | --- | --- | --: | --- |
| 2026-07-29 | `8b7c245bc7a2..b04d728249e1` | 已完成 | 25 | [`2026-07-29-archive.md`](./2026-07-29-archive.md) |

当前目录只保留三类文件：

- `README.md`：入口、状态定义和维护规则。
- `<日期>-archive.md`：一个已完成同步周期的唯一事实来源。
- `template.md`：新同步周期的临时工作台模板。

不再为每个上游提交创建独立文件。提交状态、同步方式、过滤内容和本地提交映射统一维护在周期档案中，避免多份状态源漂移。

## 状态定义

| 处理结果          | 含义                                             |
| ----------------- | ------------------------------------------------ |
| `待处理`          | 已进入扫描范围，尚未完成评估或实施               |
| `评估中`          | 正在分析适用范围、依赖或验证方案                 |
| `已同步 · 全量`   | 上游提交的全部变更均已进入当前项目               |
| `已同步 · 部分`   | 适用内容已进入当前项目，另有明确的永久过滤项     |
| `已过滤 · 跳过`   | 与当前项目相关，但已有等价实现或明确保留本地方案 |
| `已过滤 · 不适用` | 只涉及当前项目未保留的应用、文档或演示代码       |

`已同步 · 部分` 必须分别写明已同步内容、待后续同步内容和永久过滤内容。完成周期的待后续同步数量必须为零；否则该周期仍是工作台，不得归档。

## 默认范围

优先评估以下目录：

- `apps/admin`
- `packages`
- `internal`
- `scripts`
- 根目录前端工程配置

`apps/server` 是本项目独立维护的 Spring Boot 模块，除非上游提交涉及共享 monorepo 工具链，否则不属于 Vue Vben Admin 同步范围。

以下内容默认过滤，但共享运行时能力仍需判断是否应映射到 `apps/admin`：

- `apps/backend-mock`
- 未保留的上游 UI 应用
- `playground` 演示、示例路由和演示语言包
- 上游文档站 `docs/src`
- 上游社区仓库专用配置、发布和 changeset 内容
- 已删除应用、UI 框架、mock、文档站和示例产生的依赖

## 同步流程

1. 获取上游 `main`，记录不可变的完整基线 SHA 和目标 SHA。
2. 使用固定基线扫描 first-parent 历史：

   ```bash
   git rev-list --first-parent --reverse <baseline-sha>..<target-sha>
   ```

3. 从 [`template.md`](./template.md) 创建本周期工作台，将扫描结果一次性填入主表。
4. 逐项记录处理结果、同步方式、适用范围、过滤内容和本地代码提交。
5. 代码同步完成后执行完整性审计，确认提交覆盖、共享文件差异、依赖过滤和验证结果。
6. 待处理和待后续同步均为零后，将工作台命名为 `<日期>-archive.md`，并在本 README 增加入口。

## 管理约束

- 一个完成周期只有一个归档文件，归档是该周期唯一事实来源。
- 主表必须覆盖基线到目标之间的全部 first-parent 提交，且每个提交只出现一次。
- `已同步 · 全量` 不得存在过滤项；存在范围外内容时必须标记为 `已同步 · 部分`。
- 本地代码提交先于档案提交；档案中的提交映射不得填写档案自身的提交。
- 完成周期归档后保持只读。新上游目标创建新周期，不覆盖历史状态。
- 详细命令日志不长期保存，只保留可复核的最终结论、异常和已知警告。
