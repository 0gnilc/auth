Authorization architecture report

Authz 授权与权限校验分层报告

范围：先澄清 authz 底层模型，不展开 Web 环境 implementation 分析或改造。

核心结论

authz 由两个功能模块组成：授权和权限校验。权限校验从 AccessDecision 开始；授权围绕访问事实、provider 和拒绝处理展开。第二层 helper seam 包含：AccessEnvironmentResolver、AccessIdentityResolver、AccessTargetResolver。

1. Authz 的两个功能模块

授权（Authorization）

授权负责为一次访问准备事实和权限集合：访问环境、访问身份、访问目标、已授予权限、所需权限，以及拒绝后的环境动作。授权不等于单个 AccessDecision。

权限校验（Permission Checking）

权限校验由 AccessDecision module 负责：它只比较 granted permissions 与 required permissions，并返回 allow/deny，不解析权限来源，也不处理拒绝响应。

3. 第一层：授权与权限校验核心 module

Module 所属功能 职责
AccessDecision 权限校验 判断 granted permissions 是否满足 required permissions，只返回 allow/deny。
GrantedPermissionsProvider 授权 根据 AccessContext 提供已授予权限。
RequiredPermissionsProvider 授权 根据 AccessContext 提供所需权限。
AccessContext 授权事实 承载 AccessEnvironment、AccessIdentity、AccessTarget 和 attributes。
Permission 权限值 provider implementation 围绕它产出权限集合，decision 围绕它执行匹配。
AccessDenied 访问拒绝入口 决策失败后的全局唯一入口 module，通过 denied 执行访问拒绝，不参与权限校验。
AccessDeniedContext 拒绝处理上下文 承载执行环境拒绝处理数据，与授权事实 AccessContext 分离。
AccessDeniedHandler 拒绝处理策略 可存在多个 implementation，只处理自己支持的 AccessDeniedContext。

4. 第二层：组合式 adapter/helper seam

AccessContextAdapter<T>

执行环境对象进入 authz 的主 seam。它输出完整 AccessContext，而不是把原始执行环境对象交给第一层。

AccessEnvironmentResolver<T>

adapter implementation 内部的 environment helper seam，只提取 AccessEnvironment。

AccessIdentityResolver<T>

adapter implementation 内部的 identity helper seam，只提取 AccessIdentity。

AccessTargetResolver<T>

adapter implementation 内部的 target helper seam，只提取 AccessTarget。

四者是组合关系：adapter 可以组合 environment resolver、identity resolver 与 target resolver，也可以自己直接构造 environment、identity 和 target。resolver 不反向依赖 adapter，adapter 也不强制依赖 resolver。

环境入口抽象实现 module

  • 负责授权前准备。
  • 准备 AccessEnvironment、AccessIdentity、AccessTarget 和 attributes。
  • 组合当前环境的 AccessContextAdapter 与全局 AccessDecision。
  • 决策失败后调用全局 AccessDenied，由它执行访问拒绝；默认 implementation 可调用多个 AccessDeniedHandler 策略。

Provider 授权实现 module

  • 负责 concrete GrantedPermissionsProvider / RequiredPermissionsProvider implementation。
  • 根据 AccessContext 产出 granted/required permissions。
  • 通过 supports(AccessContext) 做环境参与判断。
  • 不依赖环境入口 implementation。

Scope note

本轮不展开 Web 环境 implementation

当前报告只澄清 authz 底层分层、补齐 AccessTargetResolver 抽象，并确认第三层两个功能模块之间的低耦合关系。具体环境入口 implementation 的拆分、迁移和重构应作为后续单独议题处理。
