Authorization architecture

com.gnilc.auth.authz 分层架构图

范围：仅展开 com.gnilc.auth.authz 相关结构，包括 core 授权抽象、Servlet 适配层与 RBAC 业务实现层。 本文档用于统一预览当前 authz 模块的分层边界、组件职责、子组件关系与运行时主链路。

Layer 1

核心抽象层

定义授权判断最小闭环：访问上下文、权限 provider、授权决策与拒绝处理，不关心 Servlet 或 RBAC 细节。

Layer 2

Servlet 适配层

把 Servlet 请求包装并翻译为核心 AccessContext，并在拒绝时把处理动作落回 Servlet 语境。

Layer 3

RBAC 业务实现层

把用户、角色、权限、菜单、缓存和事件接入核心 provider SPI，提供真实的授权数据与后台管理能力。

2. 核心抽象层组件

  • AccessContext：一次授权判断的统一事实载体。
  • AccessIdentity：当前访问主体的抽象身份。
  • AccessTarget：当前受保护资源或访问点。
  • AccessContextAdapter<T>：把具体运行时对象翻译成授权核心输入。
  • DelegatingAccessIdentityResolver<T>：按顺序挑选合适 handler 解析身份。
  • GrantedPermissionsProvider：提供“当前身份拥有什么权限”。
  • RequiredPermissionsProvider：提供“访问当前目标需要什么权限”。
  • AccessDecision：根据上下文、已授权限和所需权限决定放行或拒绝。
  • AccessDenied：统一拒绝访问出口。

3. Servlet 适配层组件

  • ServletAuthorizationFilter：Servlet 世界进入授权核心的桥接入口。
  • ServletRequestContext：包装 request / response / chain 的轻量对象。
  • DefaultServletAccessContextAdapter：固定 environment 为 SERVLET 并组装身份和目标。
  • DefaultServletAccessIdentityResolver：使用 handler 链解析身份，兜底 anonymous。
  • DefaultServletAccessTargetResolver：从 URI 与 Method 构造访问目标。
  • ServletAccessDeniedContext：拒绝访问时把 request / response / chain 交给 denied handler。

4. RBAC 业务实现层组件

  • RbacGrantedPermissionsProvider：把用户身份映射为已授权限。
  • RbacRequiredPermissionsProvider：把访问目标映射为所需权限。
  • PermissionCache：provider 读取权限数据的缓存门面。
  • DatabasePermissionCacheLoader：从服务层装配授权读模型。
  • RbacAuthzEvent：描述影响授权结果的数据变更。
  • PermissionCacheResetEventListener：事务提交后触发缓存失效。
  • Controller / Service / Dao / Entity：提供 RBAC 后台管理与持久化能力。

5. 授权运行时主链路

  1. ServletAuthorizationFilter 接收 Servlet 请求。
  2. 构造 ServletRequestContext。
  3. DefaultServletAccessContextAdapter 解析出 AccessContext。
  4. AccessDecision 读取 granted / required 权限。
  5. core 的 delegating provider 聚合 RBAC provider 结果。
  6. RBAC provider 通过 PermissionCache 读取授权读模型。
  7. 决策通过则继续 filter chain，失败则进入 AccessDenied。

6. RBAC 数据变更与缓存失效链路

  1. 后台管理 API 调用 RBAC service 修改权限、角色、用户关系或菜单关系。
  2. service 发布 RbacAuthzEvent。
  3. PermissionCacheResetEventListener 在事务提交后处理事件。
  4. PermissionCacheResetPolicy 推导缓存影响面。
  5. PermissionCacheResetExecutor 执行本地缓存失效。
  6. 存在 Redis transport 时，通过 Redis 广播到其他节点并触发远端失效。

7. 分层边界速记

核心层只定义机制

核心层不关心请求来自 Servlet、MQ 还是其他环境，也不关心权限数据来自 RBAC、ACL 或外部系统。

Servlet 层只做适配

Servlet 层把 request 翻译成 AccessContext，把拒绝处理翻译回 response，不承载 RBAC 业务规则。

RBAC 层只提供数据实现

RBAC 层实现 provider SPI，负责用户、角色、权限、菜单、缓存、事件与管理 API。
